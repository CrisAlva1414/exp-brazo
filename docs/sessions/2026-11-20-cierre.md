## Arquitectura

Cuatro capas independientes (ADR-001): **percepción**, **decisión**,
**actuación** y **supervisión**. Cada una puede fallar o reiniciarse sin
matar a las otras. Idempotencia por `event_id`; límites duros dentro del
adaptador de robot. SDK de referencia Dobot-Arm/TCP-IP-Python-V4, puertos
29999/30003/30004, modo **stream** (ADR-002) con feedback de puerto
30004.

Stack de cierre: MediaPipe **Tasks API 0.10.35** con modelos `.task`
vendorizados (ADR-004), NumPy 2.2.6, OpenCV contrib 4.12.0.88, FastAPI
0.139 / Starlette 1.3.1, frontend vanilla sin CDN.

## Hardening de seguridad

- **Token de acceso**: se genera en cada arranque cuando escucha en
  loopback; el HTML lo inyecta en un `<meta>` y el frontend lo usa en
  API y WebSocket. Sin token → `401`.
- **Bootstrap remoto autenticado**: con `--allow-remote`, `GET /` ya no
  es público. El operador abre `http://<host>:<puerto>/?token=<EXP_BRAZO_TOKEN>`;
  el guard valida el token, sirve el HTML y setea la cookie de sesión
  `exp_brazo_session` (`HttpOnly`, `SameSite=strict`, `Max-Age=12h`,
  `Secure` si el esquema es HTTPS). A partir de ahí el navegador usa la
  cookie y `/` ya no acepta acceso anónimo. El frontend limpia el `token`
  de la barra de direcciones con `history.replaceState`.
- **Cabeceras de bootstrap**: `/` y `/api/*` responden con
  `Cache-Control: no-store` y `Pragma: no-cache`; los cuerpos JSON de
  escritura tienen tope de 1 MB (`413` si se excede).
- **CSRF por `Origin`**: métodos de escritura con `Origin` ajeno → `403`.
- **`TrustedHost`** y cabeceras defensivas: `nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, CSP
  local.
- **Bind loopback por defecto** (`127.0.0.1`); otro host sin
  `--allow-remote` aborta el arranque. Para LAN: `--allow-remote` +
  `EXP_BRAZO_TOKEN` (mínimo 24 caracteres).
- **Límites físicos inmutables**: `PHYSICAL_JOINT_ENVELOPE` en
  contratos; los `joint_limits` configurables solo se pueden **achicar**,
  nunca ampliar más allá del envelope.
- **Validación de home**: `home_joints` debe tener 6 valores finitos y
  caer dentro de `joint_limits` (validadores pydantic en `contracts.py`).
- **Dobot**: parseo estricto de respuestas, estado `FAULT` ante errores
  de feedback, y reconexión con reintento (backoff hasta 15 s). Ante
  corte de comunicación el brazo queda en la última pose; al reconectar
  se fuerza el regreso a home (ADR-002).
- **Replay confinado**: las rutas de replay/upload deben quedar dentro
  de `recordings/`; rutas externas se rechazan.
- **Caps de upload/JSON**: upload de replay con tope de
  `200 * 1024 * 1024` bytes (200 MB) por archivo y cuota total de
  `1 GB`; límite de listado de eventos acotado a `_MAX_LIMIT = 10_000`;
  cuerpos JSON de escritura limitados a 1 MB y cuerpos no parseables o
  no objeto rechazados.
- **Cotización de configuraciones**: `BehaviorStep`, `Behavior`,
  `SupervisorConfig` y `DashboardConfig` tienen rangos explícitos
  (duración/pausa, cantidad de pasos, backoff, heartbeat, logs) para
  evitar valores absurdos desde el dashboard.
- **IP del robot**: con `adapter: dobot` se rechazan loopback,
  link-local, unspecified y multicast; se permiten direcciones
  privadas/RFC1918.
- **`validated` no falsificable**: `PUT /api/behaviors` fuerza
  `validated=false` en todos los comportamientos recibidos por API, así
  la UI sigue mostrando "SIN VALIDAR" hasta una validación real.
- **Feedback perdido**: si el feedback del Dobot se cae tres veces o
  entra en `FAULT`, `MovJ` no se envía y los comportamientos se abortan
  antes de ejecutar pasos restantes.
- **CSV safe**: exportación a CSV pasa por `_csv_safe` (escapa
  fórmulas/valores peligrosos).
- **Permisos**: directorios `0o700`, archivos de config/versiones/logs
  `0o600`.
- **Dependencias parcheadas**: `requirements.txt` fija versiones
  resueltas (p. ej. `cryptography==44.0.3`, `Jinja2==3.1.4`,
  `setuptools==75.1.0` presentes en el `.venv`) sin dependencias
  pendientes de seguridad conocidas en el set instalado.

## Pendientes / SIN VALIDAR

- Deltas, poses de home, límites articulares y umbrales de gestos están
  **SIN VALIDAR** contra el brazo físico y contra personas reales. No
  ejecutar movimientos en hardware real sin revisión y prueba supervisada.
- La cámara de este equipo rinde ~5 FPS; puede ser insuficiente para la
  latencia esperada en feria (verificar en el equipo definitivo).
- El Dobot **no fue probado físicamente**: el modo stream y el feedback
  del puerto 30004 son firmware-dependientes (ADR-002).
- La UI no fue validada visualmente en navegador (solo API/smoke).
- `wheels/` son para **linux x86_64 / py3.12**; en otra plataforma
  rehacer con `./install.sh --fetch-wheels`.
- El paro de emergencia físico sigue siendo la única garantía real de
  seguridad; la pausa por software es complementaria.


## Actualización de hardening (segunda pasada)

Se corrigió un bypass **ALTO** detectado por `security-reviewer`: en modo
`--allow-remote`, `GET /` era público e inyectaba el token en el HTML, de
modo que cualquier host de la LAN podía obtenerlo. Ahora el bootstrap
remoto usa `/?token=<EXP_BRAZO_TOKEN>`, setea una cookie de sesión
`HttpOnly`/`SameSite=strict` y retira el token de la URL visible. También
se agregaron cotas de configuración, rechazo de IPs no enrutables para el
Dobot, bloqueo de `validated=true` por API, aborto de movimiento sin
feedback y cuota total de uploads.

Verificación de esta pasada: `251 passed` (`.venv`), `250 passed, 1
skipped` (sistema), `ruff` limpio en ambos intérpretes y smoke real con
`--mock --port 8060` (root 200, token en meta, `/api/status` con token
200, proceso terminado con `kill -9` y cámara liberada).

- **Host LAN**: `create_app` acepta `effective_host`; `_allowed_hosts` incluye el host de `--host` y las IPs locales del equipo (sin `psutil`). Unit test con `192.168.1.10:8071` y `Host` real.

- **Gate de seguridad**: el último audit dio PASS con medios residuales documentados. Por pedido del usuario se omitió el re-test de seguridad en este cierre (operación offline).
